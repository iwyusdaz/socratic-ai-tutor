# Decision log

Key design decisions with alternatives considered, rationale and evidence. Numbered for reference; the README summarizes the top ones.

| # | Decision | Alternatives considered | Rationale and evidence | Date |
|---|---|---|---|---|
| D1 | **Narrow subject scope: linear equations in one variable** | General homework helper; multi-subject tutor | Correctness is mechanically checkable and the misconception taxonomy is well documented, so evaluation is actually possible. Generalization is stated as future work, not assumed. | 2026-10-25 |
| D2 | **Hint ladder with a last-resort full solution (L0–L5)** | Never give answers; give answers on request | Endless refusal causes unproductive struggle and dropout; consolidation after struggle is the evidence-based pattern (Kapur 2008: productive failure needs structure after; Sweller et al. 2019: worked examples for novices, faded as competence grows). L5 is gated behind a worked example of a *similar* problem. | 2026-10-25 |
| D3 | **Committed naive v1 baseline prompt** | Start with the best prompt; no baseline | Improvement must be attributable. A deliberate floor makes the default "helpful assistant" failure modes visible and measurable (leakage, correcting instead of diagnosing, verbosity). | 2026-10-25 |
| D4 | **v2/v3 are published as DRAFTS, to be revised after measured failures** | Write v2/v3 as final now | The portfolio rule binds: each version must respond to the previous version's *measured* failures. Writing them as final would fabricate the iteration loop. The changelog states this explicitly. | 2026-10-25 |
| D5 | **Answer-leakage rate as the headline metric** | Average rubric score as headline | Leakage is the failure that defeats the whole design (the learner stops thinking). It is binary, comparable across versions, and directly tied to the guardrail. Rubric averages are reported alongside. | 2026-10-25 |
| D6 | **Blind A/B/C scoring with two judges + human primary** | Self-scoring; single judge | Scoring bias: the prompts were AI-drafted, so the panel is blinded (codes, gitignored map), the script refuses a judge that matches the tutor model, agreement (percent + Cohen's kappa) is reported, and human scoring of the blind sheet remains primary with a second-scorer protocol prepared. | 2026-10-25 |
| D7 | **Scripted cases + adaptive simulated learner as separate methods** | Only scripted; only free simulation | Scripted turns are repeatable and comparable but don't adapt (stated limitation); the adaptive persona pipeline (MODEL_C, five misconception personas) adds reactivity while staying clearly labeled as simulation that cannot show learning. | 2026-10-25 |
| D8 | **Demo Option B (bring-your-own-key) + Option A transcripts page, no proxy** | Hosted proxy with the author's key; demo only, no transcripts page | A public proxy holding a shared key without authentication and rate limits is unbounded cost exposure. BYO-key keeps the key in memory only (never localStorage/cookies/logs), password-masked with a clear-key control, no network before a key exists, provider CORS policy flagged. The transcripts page keeps the zero-cost path honest ("coming soon — pending real evaluation runs"). | 2026-10-25 |
| D9 | **Plain-text math notation** | Rendered math (KaTeX/MathJax) | Screen readers announce `3x + 5 = 20` correctly as text; rendered math often announces badly or not at all without extra setup. Matches the tutorial scope (no fractions notation needed). | 2026-10-25 |
| D10 | **ariaSnapshot fallback instead of Guidepup/VoiceOver automation** | Claim automated VoiceOver testing; skip screen-reader checks | Guidepup does not support macOS 27 (verified at workspace level). Fallback: Playwright `ariaSnapshot()` captures + 38 scripted keyboard/reflow checks, plus a prepared manual VoiceOver protocol. No screen-reader testing is claimed anywhere. | 2026-10-25 |
| D11 | **Chat UI pedagogy: wait time rendered as "no flooding"** | Simulate delays to imitate teacher wait time | In chat, the pedagogical function of wait time (thinking space) is protected by short single-question turns that hand the turn back — not by artificial delays. Encoded as P6. | 2026-10-25 |
| D12 | **Two demo entry points share one accessibility baseline** | Minimal demo without accessibility work | The demo is the artifact reviewers will actually touch; the accessibility requirements (log region, labels, focus management, contrast, reflow) are enforced by scripted tests, not good intentions. | 2026-10-25 |

## Revisions from agent review, 2026-10-26

The first agent review ([evaluation/agent-review.md](evaluation/agent-review.md) — separate reviewer agent, fresh context, same-model limitation stated) reproduced two pipeline-breaking bugs and found two protocol leaks. Findings and dispositions:

**MUST-FIX (fixed):**

- **F1 — `eval/score.mjs` aggregation was broken; results tables could never populate.** (a) Per-criterion loops read `C1_…` keys while judge verdicts and stubs use `c1_…` — per-criterion agreement was always empty. (b) The de-blinding filter read a nonexistent `pairs[i].code` instead of `b.blind_code` — per-version rows were always empty, so even a real run would have regenerated an all-PENDING `summary.md`. Both fixed; verdict keys are also normalized (a judge answering `C1_…` despite the schema can no longer be silently skipped). The dry run now **asserts** the summary populates (per-criterion agreement, per-version averages, leakage rate) and exits 1 naming any empty cell. Verified: the fixed dry run fills all stub cells (clearly labeled DRY RUN); a deliberately re-broken copy of the script exits 1 with 9 named problems. The README/landing claim "verified end-to-end in --dry-run" was corrected to "dry-run mechanics verified; summary population asserted".
- **F2 — T28's scripted turn contradicted itself mathematically** ("I subtracted 2 from both sides … so 5x = 20" is wrong for `5x − 2 = 18`; subtracting gives `5x − 4 = 16`). Fixed to "I added 2 to both sides" — matching T08, which uses the same problem correctly.

**HIGH (fixed):**

- **F3 — human-scoring blinding leaks.** `eval/results/scores/blind-scores.json` and `agreement.json` embed the version→code map (`meta.blind_codes`) and were committable; the readable transcripts live in version-named directories with versions in their headers. Now: both judge outputs are gitignored (they are for de-blinding/audit only); a documented export command (`node eval/export-blind-transcripts.mjs`, output to gitignored `eval/results/blind-transcripts/`) re-packages transcripts under blind codes with the version stripped and refuses to write if a version name survives; METHODS.md §7, `eval/results/README.md` and the blind-second-scorer protocol state exactly what a scorer receives and must never receive.
- **F4 — L5 "legitimate vs leakage" was defined inconsistently and missing from the v2/v3 prompts.** One two-part definition now lives in [spec/hint-ladder.md](spec/hint-ladder.md) (leakage = an answer, or a bare guess confirmed/denied without a substitution check, before a genuine attempt AND two hints, **or** any full solution before L4 was tried; a ladder-exhausted L5 is legitimate) and is cited by [spec/guardrails.md](spec/guardrails.md) G1, [eval/rubric.md](eval/rubric.md) (C1 anchors + aggregation) and the judge prompt in `eval/score.mjs`. The v2/v3 drafts gained the L5 last-resort rule (v2 rule 6, v3 rule 10; the demo's inline v3 copy synced) — a drafting fix aligned with D2, recorded in [spec/prompts/prompt-changelog.md](spec/prompts/prompt-changelog.md) as "Draft revision 1" (before any run; not results-driven).

**MEDIUM/MINOR (fixed):** no-key signpost added to the demo's disabled state ("No key? See the example transcripts") plus plain-language parentheticals for "OpenAI-compatible", "base URL" and "temperature 0" (target learners are 14–16); structured review form added at [evaluation/human-protocol/review-form.md](evaluation/human-protocol/review-form.md) (modeled on the review itself, so future review passes are comparable); guardrails G3's link to the nonexistent `docs/demo/README.md` now points at the demo page's storage section; `spec/misconceptions.md` M1's self-contradictory example corrected and a one-sentence T16 M1-vs-M2 justification added; the tag vocabulary is declared in `eval/test-cases.json` meta (`diagnose-M1…M5`, `no-leak-before-attempt`, `clarify`) and `G5` added to T15; rubric C2's scope note corrected (all of T11–T18 carry G5); T31's turn now states the unstated +4 step; METHODS.md no longer cites the unresolvable workspace TOOLS.md; README/landing disclosure tense updated ("has audited") now that the review artifact exists.

**Not reproducible — verified, no change:**

- *"Start over does not restore the log hint."* Probed in a real browser: the hint is CSS (`#log:empty::after` in `docs/demo/style.css`); after Start over the log is empty and the hint re-renders (computed pseudo-element content identical before and after). The keyboard suite covers Start over separately (38/38). Recorded here instead of "fixed".
- *Local-only axe artifact.* Auditing `docs/demo/index.html` as a bare file target yields one `incomplete` color-contrast entry because the audit tool's per-file serve root cannot resolve the demo's `../assets/site.css` (the button then renders with UA-default styling). Serving `docs/` as an HTTP root — or auditing the live site — gives **0 violations, 0 incomplete** on all three pages; the original pre-revision HTML reproduces the artifact identically. Not a regression; noted so future audits serve the root.
